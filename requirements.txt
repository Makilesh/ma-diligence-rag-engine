# NOTE: PyTorch is intentionally EXCLUDED from this file, because the right
# wheel depends on the machine's GPU and CUDA toolkit. Install it separately:
#
#   pip install --force-reinstall --no-deps torch \
#       --index-url https://download.pytorch.org/whl/cu128
#
# `--force-reinstall --no-deps` matters. A plain `pip install torch
# --index-url ...` reports "Requirement already satisfied" when any torch is
# present and leaves a CPU build in place — the wheels differ only by local
# version tag (2.12.1+cpu vs +cu128), which pip does not treat as an upgrade.
# That is how this project silently ran BAAI/bge-m3 and bge-reranker-v2-m3 on
# CPU while an idle RTX 5070 Ti sat next to them.
#
# cu128 or later is REQUIRED for Blackwell cards (RTX 50-series, sm_120).
# Earlier builds install cleanly and then fail at the first forward pass with
# "no kernel image is available for execution on the device".
# Older GPUs: cu118 / cu124. No GPU: omit the index URL for the CPU build —
# everything still works, roughly 5x slower through retrieval.

# KNOWN MISMATCH, deliberately not "fixed" by version roulette.
# 2.0.25 warns "You're using incompatible versions of langgraph and
# checkpoint-postgres" because its guard wants langgraph >= 0.5, while this
# project pins langgraph <0.3 (the graph is written against the 0.2 API).
#
# Left as-is because the alternative changes are both worse bets than a warning:
# upgrading langgraph crosses three minor versions of a library this project's
# entire control flow is built on, and downgrading the checkpointer trades a
# known-good component for an unknown one. The Postgres saver was verified
# working on this pair — 764 checkpoints across 105 threads written and read
# back (see DECISIONS_LOG Decision 26) — so the warning describes a risk that
# has not materialised here.
#
# Revisit when the graph is next touched, not before a demo.
